# MACS J1149.5+2223 (HFF)

Field note for the exotic-lens screens on the HFF CATS map model `macs1149-cats` (D-033, D-035). The cluster
is at z = 0.543. Every number below is `observed`, `derived` or `model_prediction` as labelled, and every
threshold is an ASSUMPTION (D-029, D-031, D-034, D-035). No physical interpretation is made.

## Data (accessed 2026-10-08)

- **JWST (`observed`):** CANUCS GTO program 1208, NIRCam observation 8, association `t004`, all 8 PUBLIC
  level-3 bands: `jw01208-o008_t004_nircam_clear-{f090w,f115w,f150w,f200w,f277w,f356w,f410m,f444w}`.
  - One MAST position query (177.3988, +22.3985, r = 0.02°) found public NIRCam level-3 imaging from 1208,
    PEARLS 1176 (o231_t011, 8 bands), 1199 (o005_t001, 5 bands), 2883, 5890 and 6882. 1208 was chosen for
    its depth (6,399 s per band) and its 8 bands; every band's `s_region` contains the cluster position.
  - jwst 3.0.0 for every band. `_cat.ecsv` 2.9–5.0 MB; `_i2d.fits` 1.65 GB (short wavelength) and 344 MB (long
    wavelength). The `_i2d` files are never downloaded: forced photometry and cutouts read S3 byte ranges.
  - Config [`configs/macs1149.yaml`](../../configs/macs1149.yaml) (`macs1149_v1`; `stages:` identical to
    `configs/reference_sample.yaml`). Manifests: `data/manifests/macs1149.ecsv` (8 catalogs with sha256) and
    `data/manifests/macs1149_products.ecsv` (16 level-3 products with S3 URIs).
- **DJA:** none. MACS1149 is not in the DJA v7 imaging index, and `curl -I` on
  `grizli-v2/JwstMosaics/v7/<name>-grizli-v7.{0..5}-fix.eazypy.zout.fits` (and `_phot.fits`) returned no file for
  `macs1149`, `m1149`, `macs1149clu`, `macs1149-clu`, `m1149clu`, `macs1149p22`, `j114936p2223` and similar
  names. **Consequence:** no photo-z, so `images` cannot test counterpart redshifts and `radial` cannot drop
  cluster members or foreground sources.
- **Second lens model for the D-036 check (`model_prediction`):** Sharon v4cor (Lenstool), HFF HLSP
  `https://archive.stsci.edu/pub/hlsp/frontier/macs1149/models/sharon/v4cor/`, x/y deflection maps (arcsec),
  64,008,000 bytes each, sha256 `44f1d21a78cead051c08295d13d7c9189638971cf1e9445bb2caa641a129324f` (x) and
  `54508deb502d9bcafca9733c3b28f3b4d794b64f11167589b56c1fc37d66a15c` (y). They were loaded through
  `lensmodel.MapLensModel` (z_lens 0.542, H0 70, Ωm 0.3; the map headers carry no redshift; against CATS's 0.543 this changes D_LS/D_S by < 0.1 %) in scratch code only; they are not a `MODELS` entry.

**4. Counter-images (`model_prediction` / `derived`).** 45 systems, 159 predicted images (0.25″ grid):

**5a. Flux ratios (`derived`).** 145 images: consistent 19 (systems 6, 7, 16, 18, 21, 31, 1019, 1192; ratios

**5b. Radial screen (`derived`).** 527 elongated sources within 100″; 48 diffraction-spike segments dropped

p_random < 0.05: null.** Caveat: without photo-z, cluster members and foreground galaxies stay in the sample.

## Limits

- No DJA photometry or photo-z for this field (see Data).
- Sharon v4cor is the only second model checked; it was fitted to an overlapping HFF-era constraint set, so
  agreement between the two models is not independent evidence.
- System 16's redshift is a lens-model fit; a spectroscopic redshift would make the test decisive.
- `forced_check` labels the far image of system 16 `recovered` (6.7σ at 0.95″), but fixed-position photometry there
  gives 0σ, so that peak is probably a neighbour and the `recovered` count is overstated by one. The image is not
  testable either: a z scan (CATS and Sharon, z = 2–5) moves it 3–5.5″ between z = 2.5 and 3.0 (μ 4.1–5.9). Forced
  photometry along that track could fix system 16's redshift (TASKS).
