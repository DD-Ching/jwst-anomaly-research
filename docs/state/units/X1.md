# Unit X1: far-side Simpson–Visser hot spots at Sgr A* (trial unit, D-083)

**Question.** Does any observable separate a hot spot orbiting on the *far* side of a Simpson–Visser (SV) throat
from an explicit ordinary model, at a precision GRAVITY or EHT actually reach? The ordinary model is GRAVITY's
same-side orbiting hot spot plus a static component with a stated offset and flux.

**Origin.** S0 = #172 (provisional, needs-human). That work found the image bound b < b_c(a). Against the single
averaged GRAVITY loop it gives only summary-level gaps, and a ≈ 7–9 M is not distinguished.

**Premises (unestablished, carried forward):**
- an SV throat at Sgr A*;
- a far-side accretion flow;
- reflection symmetry;
- Keplerian spots;
- P_pol = P_orb.

None of these bears on usable communication.

**Total budget: 20 h:** F0 2 + S1 7 + S2 6 + S3 2 + S4 2 + reserve 1. Rules version: trial-2026-10-12.1.

## Tolerances, set from the observables (not a generic 5 %)
- **Astrometric centroid.** GRAVITY's per-point astrometric scatter is tens of µas, and the summary loop radius
  is ± 9 µas (#172). The tracer's centroid error must therefore be ≤ 1 µas (≈ 0.2 M at θ_g = 5.12 µas), which is
  well below the smallest discriminant of interest (≥ 5 µas).
- **Flux / light curve.** NIR flare light curves are compared at the few-% level, so the relative flux error must
  be ≤ 0.5 %.
- **Critical impact parameter b_c(a)** (exact formula): 1e-4 relative.
- **Image positions vs a published figure:** figure-read only. These are qualitative checks and are never counted
  as quantitative validation.

## S1 checks (written before any S1 run)
1. Schwarzschild limit (a → 0, near side): the deflection angle against the exact elliptic-integral value at
   b = 6, 8, 20 M, to 1e-6 relative.
2. b_c(a) from the tracer's capture/transmission boundary against the analytic b_c(a) of `scripts/wh_farside.py`,
   for a ∈ {2.1, 3, 5, 7}: 1e-4 relative.
3. A Schwarzschild hot spot at R = 9 M, i = 155°: the centroid loop radius against (R + 1) θ_g, GRAVITY 2023 App. A
   (an approximation, so the check is ≤ 0.5 M), and against an independent public code if one runs within the
   budget (see "Tool decision").
4. Far side: every traced transmitted ray has b < b_c(a) (exact); a qualitative comparison with 2408.07350 Fig. 7
   (figure-read).

- **Static component and errors:**
  - Sgr A* positions are referenced to S2.
  - Per-point errors are about 10–30 µas per 5-min exposure.
  - Metrology footprint errors dominate before 2022.
  - The centre is degenerate with the orbit radius (GRAVITY 2020d §4).
- **There is no explicit static-component term in the published astrometric fits.** The static offset and
  fraction are therefore nuisance parameters in S2, not measured inputs.

## Tool decision (F0)
- **Gyoto** (GPL-3, tag 2.0.2):
  - it can define user metrics in Python and has hot-spot astrobjects;
  - it has no SV or wormhole metric;
  - it is not on PyPI or conda-forge, so cloud installation is uncertain;
  - whether it handles r < 0 is untested.
  - **Use:** only as an optional S4 cross-check (Schwarzschild limit, KerrBL with spin 0), if it installs within
    30 min.
- **Main tracer:** a small NumPy/SciPy null-geodesic tracer for the static, spherically symmetric SV metric over
  r ∈ ℝ. It integrates planar orbits and uses the exact symmetry rotation to build images.
  - No existing permissive code covers SV with far-side emission: OCTOPUS has no licence; Gradus.jl is Julia,
    GPL-3; the others are Kerr-only.
  - einsteinpy (MIT) integrates geodesics in a user metric and serves as the S4 second integrator for spot checks.
- **No tabulated hot-spot benchmark exists.**
  - Validation instead uses exact Schwarzschild deflection integrals, the analytic b_c(a), the a → 0 limit, and
    GRAVITY's App. A approximation.
  - A fit-level sanity check uses `avg.dat`.

## Feasibility judgement (F0)
- **(i) Model and method validation:** feasible within S1's 7 h.
- **(ii) Real-data discrimination:** weak. One machine-readable flare (10 points, errors of tens of µas, centre
  degenerate with radius), and it was already part of #172's summary. This is enough for an exploratory
  consistency check, not a decisive test.
- The unit still proceeds: there is a concrete new prediction (the far-side centroid and flux track for a stated
  ordinary model) and an affordable validation path.
- The decisive data are named as the missing input: per-flare GRAVITY 2022–2023 astrometry with error models.

## Independence of data
All four GRAVITY 2023 astrometric flares (including the three of 2018) were used in #172's summary comparison.
**No GRAVITY flare is truly held out.** Any S3 comparison with these flares is **exploratory**. A flare published
after 2023, and not used in #172, would count as held out only if it is fixed as such before S2 results are
seen.
